# Hand-Free-Game

한국어 클릭·자동 전투 게임입니다. 서버나 빌드 과정 없이 정적 파일로 실행합니다.

공개 게임: https://gmlduqzhd123-lab.github.io/Hand-Free-Game/

## 로컬 실행

저장소 루트에서 Python 3로 HTTP 서버를 실행합니다.

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000/`을 엽니다. 소리는 사용자 조작 후 시작하며, 자동 백업 복사는 HTTPS 또는 localhost에서 사용할 수 있습니다. 복사가 허용되지 않아도 백업 코드를 직접 복사하거나 파일로 내려받을 수 있습니다.

## 검증

저장·전투 회귀 테스트는 Node.js 24에서 추가 패키지 없이 실행합니다.

```bash
node --test tests/game.test.js
```

브라우저 검증에는 Python Playwright와 Chromium이 필요합니다. HTTP 서버를 실행한 상태에서 다음 명령을 사용합니다.

```bash
python3 tests/browser_smoke.py http://127.0.0.1:8000/ --output /tmp/hand-free-browser-results.json
```

기본 Chromium 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경할 수 있습니다. 제공된 HTTPS 프록시가 있으면 사용하고 TLS 검증을 유지합니다. 결과 JSON과 종료 코드로 성공 여부를 확인합니다. 실제 사용자 저장 데이터를 사용하지 않고 새 브라우저 컨텍스트에서 실행합니다.

## 게임과 저장 규칙

- 처음 실행하면 무료 자동 처리 Lv 1로 즉시 자동 전투를 시작합니다. 클릭하거나 강화할 필요가 없습니다. 기존 세이브에서 자동 공격을 아직 열지 않은 경우에도 무료로 시작합니다.
- 플레이어 경험치는 매초 5씩 오릅니다. 첫 레벨업은 약 4초 뒤이며, 다음 레벨에 필요한 경험치는 `20 + (현재 레벨 - 1) × 10`입니다. 레벨마다 전체 공격력 배율이 5%씩 증가하고, 상단에서 레벨과 경험치를 확인할 수 있습니다.
- 자동 공격은 초당 한 번, 조퇴 스킬 공격은 활성 화면에서 80ms마다 실행합니다. 느린 프레임에도 경과 시간을 보존합니다.
- 자리비움은 최대 24시간의 자동 성장과 전투를 정산합니다. 경험치는 100%, 전투 골드는 70%를 지급하며 처치·단계·보스 보상은 같은 전투 규칙을 사용합니다. 수동·조퇴 공격은 자리비움에 포함되지 않습니다. 재접속 자체에 추가 경험치를 지급하지 않습니다.
- 보스 제한 시간과 스킬 쿨다운은 실제 시간으로 흐릅니다. 일반 적의 저장 HP를 복원합니다. 16:40 달성 후에도 계속 진행할 수 있습니다.
- 내일 출근 시 플레이어 레벨·경험치, 연수학점, 보석, 교보재, 달성 업적과 누적 클릭·보스 처치를 보존합니다. 완전 초기화는 확인 후 실행하며 레벨 1과 무료 자동 공격으로 시작합니다.
- 기존 저장 키 `ys_bugfree_final_v2`를 유지하고 v1~v3 데이터를 v4로 변환합니다. 손상된 저장은 원본 보관과 복구 안내를 제공하며 자동으로 덮어쓰지 않습니다.
- 한 탭이 진행을 저장합니다. 다른 탭은 일시 정지되며 명시적으로 이어하기를 선택할 수 있습니다. 저장 실패를 안내하고 유효하지 않은 백업·실패한 가져오기·초기화로 기존 진행을 바꾸지 않습니다.
- 장기 진행의 수치 상한은 `1e100`, 강화 레벨은 1,000, 진행·클릭·처치 카운터는 `1e9`입니다. 크리티컬 확률의 상한은 50%입니다.

## 파일과 배포

`index.html`과 `styles.css`는 화면과 반응형 디자인, `save.js`는 저장 검증과 탭 소유권, `game.js`는 전투·업적·성장, `app.js`는 브라우저 이벤트·화면·소리·이펙트를 담당합니다. 파일은 같은 위치에서 로딩됩니다.

작은 모바일 화면에서도 현재 업무·경험치·자동 공격과 기본 강화 3개를 먼저 확인할 수 있습니다. 태블릿·PC는 전투와 성장을 좌우에 배치하고, 자세한 규칙은 각 탭의 도움말에서 확인합니다. 스킬은 사용 가능·작동 중·대기 시간을 구분해 표시합니다.

GitHub Pages는 `main` 브랜치의 저장소 루트에서 배포합니다. 검증된 변경을 `main`에 푸시한 뒤 Pages 빌드의 성공과 공개 URL의 실제 내용을 확인합니다. 브라우저 테스트 명령의 URL을 공개 주소로 바꾸면 배포본도 검증할 수 있습니다.
